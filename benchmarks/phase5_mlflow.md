# Phase 5 — MLflow Model Versioning

## Objective

Add model versioning to the inference platform using MLflow so that
different registered model versions can be selected at request time.

## Implementation

- MLflow used as the model registry
- Registered model: `sentiment-classifier`
- Registered versions: v1 and v2
- API supports runtime model selection using:
  - `/predict?version=1`
  - `/predict?version=2`
- Redis cache keys include the model version to prevent cross-version
  prediction collisions.
- Loaded MLflow models are cached in memory to avoid reloading the
  model on every request.

### Version-isolated caching

The same input was tested against both model versions.

The cache correctly treated the versions independently:

```text
1:I absolutely love this
2:I absolutely love this
```

This prevents a prediction generated by one model version from being
incorrectly returned for another version.

## Result

The platform can dynamically select a registered MLflow model version
at request time without modifying or redeploying the application for
each new model version.

## Note

v1 and v2 currently use the same underlying sentiment model. The purpose
of this phase was to demonstrate model registry, version selection, model
loading, and version-aware caching rather than differences in model
quality.
